# 服务层级能力

[English](guide.md) | 中文

## 变更

显式 `serviceTier` 值会按所选模型的 `serviceTiers` 校验。不声明所请求层级的路由以 `UNSUPPORTED_OPTION` 拒绝请求，而不再静默忽略。省略字段保留适配器已有默认行为；`default` 显式请求端点的默认层级，`priority` 请求优先处理。内置 Fast 控件被移除；独立插件负责控件和新会话默认策略。

最初的社区 Fast 构建仅接受恢复数据中的 `priority`，会拒绝恢复包含新显式 `default` 值的请求头。移除插件不会降级读取器或抹掉已保存选择。官方基线与社区构建是不同兼容目标，不应假定社区构建接受官方基线可保留的所有记录。

## 迁移

1. 自定义适配器仅在确实将服务层级映射到端点时，才在模型元数据中声明 `serviceTiers`。`llm-pi-ai` 中受支持的 Responses 路由声明 `default` 和 `priority`。
2. 需要保留提供方默认行为的集成应省略 `serviceTier`，仅在模型声明支持时使用显式值；记录选择之前通过 `resolveCallConfig()` 检查支持情况。
3. 使用兼容的 Fast 插件获得会话控件和可配置的新会话默认值。安装、重新配置或移除插件均不改变已有会话选择。
4. 对包含显式 `default` 的会话保留通用服务层级读取器，不使用最初仅支持 priority 的社区构建恢复这些历史。修改最新选择不会移除旧记录。
5. 确认接受的选择可在重启后恢复，不支持的值在派发前失败。人工编写的 SDK 回放和适配器测试无需提供方请求即可覆盖这些行为。
