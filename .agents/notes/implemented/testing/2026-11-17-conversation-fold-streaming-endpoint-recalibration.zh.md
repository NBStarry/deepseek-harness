# Agent Note: 对话折叠流式端点重标定

Status: implemented

[English](2026-11-17-conversation-fold-streaming-endpoint-recalibration.md) | 中文

## 问题

必需的[对话折叠流式基准](../../../../benchmarks/conversation-fold/conversation-fold.bench.client.ts) 使用由历史 12/32 ms 参考额度和共享[两倍缩放与 1.25 余量](../../../../benchmarks/support/calibration.ts) 推导出的 30/80 ms CI 上限。在未改动的基准代码上，两轮独立的正常五样本 AMD 托管运行测得 reasoning-leading-whitespace 中位数为 4,096 个片段时 30.95092/31.00177 ms，16,384 个片段时 80.904117/86.159412 ms。因此旧 30/80 上限在当前托管运行器上使必需门禁失败。本记录只认定明确授权的 测量标准变更；不声称产品性能提升，也不是新的 Mac 测量。

## 决策

只有 4,096 和 16,384 流式端点获得按端点设置的 `ciBudgetMs` 上限 **40/110 ms**。每个片段数下既有的 text/ordinary 与 reasoning/leading-whitespace 用例共用同一上限。五个全新样本、中位数规则、 完整 262144 字符负载、checksum/flush 边界、保留内存断言及预算、其它端点预算，以及共享的 `CI_TIME_SCALE=2` / `1.25` 余量均不变。源码注释指向本记录。

## 校准

| 运行 | 4,096 reasoning 中位数 | 16,384 reasoning 中位数 |
|---|---:|---:|
| CI 44012719045 | 30.95092 ms | 80.904117 ms |
| CI 44021529843 | 31.00177 ms | 86.159412 ms |

取较大的中位数。经审阅的 25% 余量得到 38.752 ms 和 107.699 ms，再向上取整到下一个 10 ms， 即授权的 40/110 ms 上限。两轮均使用 AMD EPYC 7763 托管 Ubuntu 24.04 环境与正常五样本运行， 不是 Mac 参考测量。历史 12/32 ms 参考额度与旧 30/80 门禁失败保留在 [前端性能预算](2026-09-06-frontend-performance-budgets.zh.md)记录中，不作改写。

## 备选方案

**调整共享缩放或余量。** 否决：会移动无关端点，超出明确授权的流式端点范围。

**使用动态平台、环境或 CPU 相关上限。** 否决：性能预算必须是经审阅的源码常量；未授权环境覆盖、 重试策略或平台开关。

**修改产品算法或 worker。** 否决：观察到的失败是托管运行器上的测量标准不匹配；未授权产品或 worker 改动。

## 后果

必需的流式组现在在授权的托管 CI 标准下执行 40/110 ms。先前的必需红色保留为历史证据，不报告为产品 性能问题已修复。其它基准端点与内存门禁保持原有决定。
